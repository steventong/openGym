# openGym Native iOS

openGym 的 SwiftUI 原生开发版本。仅在 `native-ios/` 内新增代码；沿用现有后端协议，不修改 Web、Android 或服务端。

## 运行

- iOS 26+；Xcode 26+（本次以 Xcode 27.1 / iPhone 17 Pro，iOS 26.5 验证）。
- 打开 `OpenGym.xcodeproj`，选择 `OpenGym` scheme 和 iPhone 模拟器，Run。
- 不需要 Swift Package、CocoaPods 或 Capacitor。模拟器使用本机服务 `http://localhost:8080`。
- 真机请填写可访问的 HTTPS 服务地址，选择自己的 Signing Team；`localhost` 在真机上指手机本身。
- 必须保留模拟器的 ad-hoc 签名和 `OpenGym.entitlements`；不要用 `CODE_SIGNING_ALLOWED=NO`，否则 Keychain 无法保存配对凭据。

```sh
xcodebuild -project OpenGym.xcodeproj -scheme OpenGym \
  -destination 'platform=iOS Simulator,id=<SIMULATOR-UDID>' \
  -derivedDataPath .build build
xcrun simctl install <SIMULATOR-UDID> .build/Build/Products/Debug-iphonesimulator/OpenGym.app
xcrun simctl launch <SIMULATOR-UDID> me.itwl.opengym
```

服务端用仓库现有 Docker Compose 启动。正常账号在网页中登录后，从「设置 → 账号 → 配对手机 App」取得一次性代码，在 iOS 设置中填写。凭据保存在 Keychain，绑定服务地址；应用不会读取 Docker 数据目录或服务端密钥。

## 本版功能

- 原生五页导航：首页、计划、训练、统计、动作库；黑色背景、绿色主色、圆角卡片参考 Web。
- 设置入口保留在首页右上角；动作库不重复提供。首页不显示账号同步状态行、体重卡片及底部累计统计。体重趋势统一放在统计页，标题右侧「添加记录」打开体重录入，无记录时也保留入口。
- 首页按所选日期的安排展示训练入口：训练日主按钮「开始训练」直接开始当日安排，次级按钮「自由训练」；非训练日主按钮「自由训练」，次级按钮「选择训练计划」。计划选择页第一项为「自由训练」，后面依次展示今日安排和已有计划；已有草稿时显示「继续训练」。自由训练无需创建或选择计划，开始后按需添加动作；草稿可重启恢复，完成后保存为不关联计划的训练历史。
- 5,632 条原版动作：中文/英文搜索、身体部位/器械筛选、列表/网格、详情、中文动作步骤、Epley 估算。
- 动作视频不打包进 App。首次打开动作时，从当前配置服务器的 `/exercise-media/clip/{id}.mp4` 下载，确认完整且可播放后保存到 `Documents/workout-videos/{id}.mp4`，再由 AVQueuePlayer + AVPlayerLooper 播放。后续优先读取本地文件，已下载视频支持离线播放；下载失败可重试，删除或损坏的文件在下次打开时重新下载。同一动作的并发加载共用一次下载，关闭详情不会中断缓存保存，但不会在后台重新启动播放。可通过“文件”App → 我的 iPhone / iPad → OpenGYM → workout-videos 查看、预览和删除文件；缓存不参与系统备份。缩略图通过 `Assets.xcassets/ExerciseThumbnails` 内的 PNG 图片资源集管理，使用 SwiftUI 标准 `Image("ExerciseThumbnails/dumbbell-bench-press")` 从编译后的资源目录离线加载；缺失图片的自定义动作显示哑铃占位图。
- 动作 MP4 无音轨（已检查仓库全部 6,554 个文件）。iOS 27+ 播放前断开播放器与系统音频的连接；旧版使用 ambient 混音，不打断或压低其他音乐。暂停、关闭详情及进入后台时释放音频会话，并通知被打断的播放器可以恢复；是否恢复由对方播放器决定。
- 账号配对、Keychain、登录续期、手动刷新、前台刷新、每 30 秒刷新。设置中未配对时显示配对表单，已配对时显示当前连接与服务器地址；「立即同步」右侧的「重新配对」经确认后重新打开表单，可取消返回原连接。
- 计划编辑：名称、动作增删与排序、组数/次数/重量/休息时间和备注；支持热身、计时、有氧、分侧、金字塔、递减、Rest-pause、最后一组力竭和相邻动作超级组。
- 计划删除：进入计划编辑页，在底部点击「删除训练计划」并确认；同步清理每周与单日排期，循环跳过已删除计划，保留历史和正在进行的训练。删除失败时保留编辑页，可重试。
- 训练排期：每周一天可以安排多个计划；单日指定计划、休息或恢复每周安排。首页按网页规则显示队列和覆盖，可合并开始多个计划。
- 历史编辑：名称、备注、日期/开始时间、时长、普通组重量/次数/完成与热身状态、动作和组的增删；重新计算训练量、个人纪录及受修正影响的已追踪重量。支持继续加载较早的历史记录。
- 原生高级训练：逐组/逐侧记录，编辑递减重量和次数、Rest-pause 小组、RIR/RPE；超级组按轮切换和休息。计时支持暂停、恢复、提前完成，草稿和计时可跨重启恢复。
- 循环排期：编辑循环名称与顺序、移入移出计划、进度显示、重新开始一轮、切回固定周；保留外部队列的归属规则，完成一轮后按网页版规则自动续轮。
- 体重记录与折线图、真实训练历史、完成组数、12 周活动图。

## AI 教练

在「训练计划」标题右侧、`+` 左边点击 `AI`。使用当前配对账号与服务器统一配置的服务，手机不保存模型密钥；设置页不重复放入口。

- 首次读取服务器的数据使用说明，确认后完成七步训练问答；已有网页授权和问答会直接复用。
- 聊天调整计划、生成新计划、评估现有训练、优化指定计划、复盘上次训练。运行状态在页面可见且 App 前台时轮询，离开后服务器继续处理。
- 查看计划的动作、处方、理由和每周安排；导入时可保留原排期。修改建议支持逐项选择，已过时的建议禁用。所有应用操作先确认，再保存同步。
- 历史建议、拒绝记录、训练复盘和撤销与网页共用 `state.coach`。教练菜单可编辑问答、设置自动评估；服务器启用社区功能时可自愿参与匿名对比。
- 计划应用、过期检查、快照和撤销复用网页纯规则，由 JavaScriptCore 执行。写入先读取最新版本，冲突时重新计算，服务器确认后再清除待处理建议；丢失响应重试不会重复导入。
- 本次接入服务器模式。手机独立 API key 模式和管理员服务配置仍使用网页/原项目客户端。

`npm run build:rules` 通过 `scripts/build-rules.mjs` 把浏览器翻译入口替换为无 DOM 的 i18n-core，原 Web 代码不修改。`CoachTests` 覆盖授权版本、导入/拒绝/撤销、过期与冲突、响应丢失、快速失败、账号切换和后台同步竞争。

模拟器交互验证可运行 `node scripts/coach-qa-server.mjs`，连接 `http://localhost:19384` 并用 `QA` 配对。该服务仅监听本机，使用虚构数据，不联系模型服务；验证结果保存到忽略目录 `artifacts/coach/qa-result.json`。不要把测试端口配置到真实手机。

## 协议

| 操作 | 现有接口 |
| --- | --- |
| 服务状态 | `GET /api/health` |
| 手机配对 | `POST /api/pair/redeem` |
| 账号/续期 | `GET /api/me` |
| 读取状态 | `GET /api/data` |
| 保存状态 | `PUT /api/data`，携带 `baseRev`、已有的 `baseWid` |
| 动作图片 | `Assets.xcassets/ExerciseThumbnails/dumbbell-bench-press.imageset`（英文动作命名的 PNG，离线读取） |
| 动作动画 | `/exercise-media/clip/{id}.mp4` |

每次写入先读取最新完整 JSON，只更改对应记录，保留客户端不认识的字段。遇到 HTTP 409，重新读取后重放狭义、幂等的操作，最多尝试三次。训练使用稳定 UUID 去重。服务端负责同步时间戳，iOS 不伪造 `stamped:true`。不静默覆盖冲突，不自动改变网页的重量单位。

编辑使用原始值、本地修改和最新服务端值进行三方比较。未修改的字段保留远端的新值；同一字段冲突时阻止保存并保留表单。数组结构发生并发修改时也拒绝覆盖，避免旧动作顺序覆盖新动作或新训练组。取消编辑不会写入服务端。

动作目录没有单独的服务端 API；`scripts/build-catalogue.py` 从现有 `catalogue/exercises` 和 `catalogue/i18n/zh.json` 生成 App 内的 JSON，沿用原始动作库的文案：简介使用英文源文，步骤优先使用原库已有中文，缺失时回退至英文。它只读取原仓库，输出到 `native-ios/OpenGym/Resources`。视频按需从服务器下载到 `Documents/workout-videos`，缩略图编译到原生 Asset Catalog；账号同步会另外合并自定义动作及收藏。

## 复用的计算规则

所有页面为 SwiftUI，视频为 AVPlayer。排期解析、训练组生成、训练量、个人纪录、分侧聚合、超级组和循环流转，通过系统 JavaScriptCore 执行仓库已有纯函数，没有 WebView。`scripts/rules/entry.js` 与 `advanced.js` 只读导入原 Web 源码，esbuild 将其打包至本目录的 `OpenGym/Resources/web-rules.js`。生成文件已加入工程，日常 Xcode 构建不需要 Node。更新仓库后，在 `native-ios` 中执行 `npm ci && npm run build:rules` 重新生成，不会修改原 Web 文件。

## 当前边界

训练和历史编辑的动作卡片提供「本次重量单位」kg / lb 切换，适合同一个动作在不同健身房使用不同标注的器械。切换会换算显示已有重量；新输入按所选单位记录，普通组、分侧和递减重量均适用。每组保留输入单位并随草稿和历史保存；实际数值始终使用账号统一单位，以兼容现有训练量、纪录与同步规则。此选项仅影响当前动作，不修改全局单位；上次训练摘要仍明确标注账号单位。尚未填写完成的重量会阻止切换，保留原输入。

尚未实现 Web 的全部功能。暂不支持原生创建通行密钥、所有进阶策略的原生设置界面、后台训练提醒或所有数据类型的离线写入。开始训练调用网页的组生成和处方规则，沿用服务器保存的进阶配置。动作计时的到期结算在训练界面运行或返回时完成；休息开始时会独立安排本地系统通知，可在「设置 → 系统通知」开关及管理权限，后台和锁屏投递遵循系统通知与专注设置。原版配置和扩展字段在同步中保留。

训练草稿、历史编辑表单和账号缓存按「服务地址 + 账号」隔离保存。输入通过原子文件替换立即写入，并保留上一份可读副本；空白数字、未完成的小数和备注原文都保留在本机。冷启动可先恢复本机账号、训练和历史编辑，再尝试联网。本机写入失败会明确提示，提交前必须先成功落盘。卸载 App 或设备损坏不在本机文件恢复能力范围内。

历史编辑关闭后保留草稿；提交使用版本检查和三方合并，读取服务器确认后才归档本次草稿。断网、409、服务器已写入但响应丢失都保留待提交内容。统计页在本机编辑尚未同步的训练标题右侧显示「未同步」及「同步」文字按钮，可直接提交；同步失败保留内容并提示原因。点击训练先进入只读预览，所有动作卡片直接展开，保留输入框与完成按钮样式但禁止操作，隐藏动作及每组菜单；「编辑记录」仍打开原有编辑模式。完成训练使用固定记录 ID 和固定结束时间重试，成功后保留本机归档。计划编辑仍使用在线保存。未配对时可以浏览动作，服务器写入需要有效账号。

训练与历史编辑共用动作页面，包括动作选择、备注、组列表、添加与删除组和前后切换；允许删空后重新添加。计时分侧组的左右侧成对增删，删除计时所属组会取消计时，删除前面的组会同步修正计时器位置。训练与历史编辑一次显示一个动作，中文名称与英文副标题仅用于展示，通过底部按钮切换动作。保存入口在右上角菜单；组间倒计时属于产生它的动作卡片，切换后计时继续。本次动作备注、计划备注及同一动作 ID 的上次训练分别显示，不跨健身房独立 ID 混合历史。计划排序按钮点击区域为至少 72 × 48 pt。

「设置 → Apple 健康」提供体重读取授权和同步开关。体重功能仅请求 bodyMass 读取权限，使用 anchored query、observer 和 background delivery；样本与查询位置先一起落盘，再同步到当前 openGym 账号。每天最后一次测量参与显示，支持 kg/lb 转换、重复同步去重、已确认的 HealthKit 删除和手动记录保护。关闭开关停止后续同步，保留已有数据；系统读取权限在健康 App 管理。iOS 不公开读取授权是否被拒绝，因此空结果不能显示为“已授权”或用于删除既有体重。HealthKit entitlement、后台交付 entitlement 与读取说明已加入工程，真机签名需支持这些能力。

2026-10-26：模拟器验证单动作切换、卡片内倒计时、菜单保存、历史编辑重启恢复与健康设置入口。自动化测试覆盖本机故障、断网、响应丢失、重复提交、并发修改及体重合并。真实 HealthKit 授权和后台唤醒尚需真机验证，模拟器不能证明后台交付效果。


休息通知在后台正常保留；手机或手表上的 App 进入前台时，会清除该设备上已送达的休息通知。使用 App 期间不显示休息通知横幅或新增通知中心记录：手机保留提示音，手表使用本地到点触感。清理已送达通知不会取消尚未到期的休息提醒。

## Apple Watch 训练伴侣

`OpenGymWatch` 是随 iPhone App 嵌入的配套训练 App，watchOS 10+；`WKRunsIndependentlyOfCompanionApp` 与 `WKWatchOnly` 都是 `false`。无需单独登录或配置服务器。OpenGym 训练由 iPhone 开始、编辑和保存；手表显示当前动作、下一未完成组、重量／次数，以及手机同源的休息倒计时。主按钮与灵动岛采用相同的状态切换：休息中显示「结束休息」，主动结束后经 5 秒防连点阶段显示「完成本组」；自然到期保留「结束休息」（记录当前组／当前侧）。完成后同步下一组，当前动作全部完成时自动切到下一个未完成动作；全部完成后提示回 iPhone 保存。手表不创建独立的 OpenGym 训练、不访问后端、不读取账号凭据或训练历史。开启 Apple 健身同步后，手表同时负责系统运动记录，详见下方「Apple 健身训练同步」。

手表完成操作通过 WatchConnectivity 自动请求手机写入，不需要用户在手机再点一次确认。手机返回成功后才推进组数；未收到回复时可重试同一请求。请求检查账号、训练、组索引和草稿版本，并保存去重回执，避免连续点击、响应丢失或手机修改动作后记错组。分侧逐侧完成，只有该组规则要求休息时才开始休息。断开连接时显示上次数据并暂停录入，不在手表累积独立离线训练。手机正在动作计时时，手表提示回手机结束计时。

手表上点击「开启休息提醒」授权后台通知，收到休息结束时间后安排本地提醒；更改／跳过休息会替换／取消旧提醒。前台使用与倒计时相同的结束时间直接触发一次触感反馈，不等待系统通知回调，也不显示系统横幅或保留通知记录；迟到的通知不会重复震动。进入后台后由 watchOS 通知机制投递，遵循系统通知与专注设置；回到前台清理已送达的休息通知，不补播已经结束的休息。前台触感日志记录相对结束时间的延迟。系统是否及时投递手机在远端修改的倒计时，以及真表触感、Always On 和锁屏体验，仍需配对真机验收。

训练主屏无需滚动即可查看动作、组数、重量／次数、心率（次/分）、活动热量与总热量（均为 kcal）、休息倒计时和状态按钮。总热量只在 HealthKit 同时提供本次训练的活动与静息能量时相加显示；缺失值显示「—」，不以 0 或自行估算替代。指标按系统采样回调更新；动作名称独占标题行，不再提供右侧「…」菜单及详情弹窗。旧健康报告仍可读取，不含总热量时保持缺失。

主操作始终由同一个按钮承载；倒计时文字与组合按钮抽为跨端共享组件，数字由系统更新。自然到零不切换按钮；主动结束休息和完成本组都进入 5 秒灰色禁用阶段，绝对截止时间由手机保存并同步。手机录入页勾选不受限制。连接失败时只显示「连接 iPhone」，覆盖完成、结束休息或重试确认；短暂断线先自动尝试 3 次、最多约 6 秒刷新连接，成功收到手机新快照后恢复操作。自动重连不会重发完成命令。动作名、组数和参数均限制一行，主屏各区域固定高度；非休息时倒计时行透明占位，按钮不会上移，按钮下方不显示提示文字。长名称与错误详情可从右上角查看。
